# 가사를 대신 찾아 주는 AI 에이전트

> 유튜브 영상 하나를 입력하면, 에이전트가 **9개의 도구를 스스로 골라 가며** 그 곡의 진짜 가사를 찾아내고,
> 일본어 곡이면 **한글 발음과 한국어 번역**까지 줄 단위로 붙여 돌려준다. 사람은 재생 버튼만 누른다.

**수행평가 4 대체 — AI 에이전트 서버 프로젝트 (자유 주제)** 제출물

이 에이전트는 데모가 아니라 **실제로 배포되어 매일 돌고 있는 서버**의 일부다.

---

## ⚠️ 이 저장소에 대하여 — 먼저 읽을 것

이 저장소는 **에이전트의 코드와 문서만 정리한 것**이다.

- **`src/` 의 코드는 원본 경로 그대로 복사한 것이다.** 문서에 적힌 파일·줄번호가 그대로 맞는다.
- **이 저장소만으로는 빌드되지 않는다.** 더 큰 개인 프로젝트의 일부라, 인증·재생 등
  AI 와 무관한 코드를 뺐기 때문이다.
  **코드를 *읽기* 위한 저장소**이지 실행하기 위한 저장소가 아니다.

이렇게 나눈 이유는 과제가 "**주제 1개를 선택해 깊이 있게**" 를 원칙으로 하기 때문이다.
주변 코드까지 전부 내면 에이전트가 어디인지 묻히므로, **평가 대상이 되는 부분만 드러냈다.**

## 1. 무엇을 푸는 에이전트인가

유튜브에서 받은 노래에 가사를 붙이려면 **"이 영상이 무슨 곡인지"** 를 먼저 알아내야 한다.
그런데 유튜브 제목은 사람이 아무렇게나 쓴 문자열이다.

```
【歌ってみた】強風オールバック / covered by しぐれうい
Ditto - NewJeans
[MV] 아이유(IU) _ 좋은 날(Good Day) (Official)
```

정규식으로 이걸 파싱하려 했고, 실제로 15개를 썼다. 그리고 **벽에 부딪혔다.**

| 규칙으로는 불가능한 것 | 왜 |
|---|---|
| 커버 영상의 **원곡 아티스트** | 제목 문자열에 답이 아예 없다. 가사는 원곡의 것이라 원곡 아티스트로 찾아야 하는데 |
| `Ditto - NewJeans` 에서 **어느 쪽이 곡명인지** | 문자열만으로는 알 수 없다. 관례(Artist - Title)로 찍으면 반대 순서 영상에서 뒤집힌다 |
| 찾아온 가사가 **정말 그 곡의 것인지** | 제목 유사도 0.85 같은 임계값은 "제목이 비슷한 **다른** 곡"을 못 거른다 |

**이건 문자열 처리 문제가 아니라 지식 문제다.** 그래서 AI 를 붙였다.

```
        └───────────┬───────────────┘
                    ▼
   ┌────────────────────────────────────────────────┐
   │            도구 선택 사다리 (6단)                 │
   │  1) Unison 싱크    videoId 정확매칭 · 단어 타이밍  │
   │  2) LRCLIB 싱크    제목/아티스트 퍼지매칭         │
   │  3) Unison 플레인                              │
   │  4) LRCLIB 플레인                              │
   │  5) 인터넷 폴백    NetEase / Bugs / lyrics.ovh   │
   │  6) 나무위키       최후 수단 · 검증 없이는 불채택   │
   └───────────┬────────────────────────────────────┘
               │  각 단의 결과를 채택하기 직전에 ↓
               ▼
        ┌───────────────────────────┐
        │  도구 B · AI 가사 검증      │  "이게 정말 그 곡의 가사인가?"
        │  AiLyricsVerifier         │  거부 → 사다리의 다음 단으로 내려간다
        └───────────┬───────────────┘
                    ▼
            가사 확정 · DB 저장
                    │
                    ▼ (일본어 가사이고, 사람이 버튼을 눌렀을 때만)
        ┌───────────────────────────┐
        │  도구 C · 발음·번역         │  ① 나무위키에서 사람이 쓴 것을 베껴 오고
        │  AiLyricsLayers           │  ② 못 찾은 자리만 AI 가 생성한다
        └───────────┬───────────────┘
                    ▼
[ 출력 ] 싱크 가사 + 줄별 한글 발음 + 한국어 번역 + 출처 표기
```

## 4. 설계 원칙 세 가지

### ① AI 는 절대 필수 경로가 아니다

키가 없거나, 할당량이 끝났거나, 네트워크가 막혔거나, 응답이 깨졌으면 **조용히 `null` 을 돌려주고
호출측은 기존 규칙 기반 로직으로 그대로 간다.** 오프라인일 수 있는 홈서버라, 이 폴백이 없으면
가사 기능 전체가 AI 에 인질이 된다.

> 실제로 API 키를 고의로 망가뜨려도 가사는 계속 나온다.

### ② 확실히 아는 것은 AI 에 묻지 않는다

가사가 일본어인지는 **유니코드 범위를 세면 확실히 안다.** 이걸 AI 에 물으면 돈과 시간이 들고
**답이 흔들리기까지 한다.** 순수 함수로 판별한다.

```
가나 = 히라가나 + 가타카나 + 반각가타카나 글자 수
가나 < 3자                              → 대상 아님
가나 / (가나+한자+한글+라틴) < 0.05      → 대상 아님
그 외                                   → 일본어 가사
```

한자만 있고 가나가 없으면 중국어일 수 있으므로 **대상에서 뺀다.** 놓치는 곡이 조금 생기지만,
엉뚱한 곡에 일본어 발음을 붙이는 것보다 낫다.

### ③ AI 의 출력은 믿지 않고 검사한다

발음·번역은 받아온 값을 **기계적으로 검증**하고, 하나라도 걸리면 그 덩어리를 통째로 버린다.

| 검사 | 걸렸을 때 |
|---|---|
| 줄 수가 다르다 | 덩어리 통째 폐기 |
| 가사 없는 줄(♪)에 값이 붙었다 | 지어낸 것 → 폐기 |
| 발음에 가나·한자·로마자가 남았다 | 음차 실패 → 폐기 |
| 번역에 가나가 남았다 | 번역 안 된 줄 → 폐기 |

**부분 수용을 하지 않는 이유**: 줄이 하나 밀리면 그 뒤 전부가 *다른 줄의* 발음이 된다.
눈에 잘 띄지도 않으면서 가장 나쁜 실패라, 의심스러우면 전부 버리는 게 싸다.

## 5. 운영 안정성 — `AiClient.cs`

에이전트 서버가 외부 API 에 의존할 때 필요한 장치들.

| 장치 | 값 | 이유 |
|---|---|---|
| **JSON 강제** | `responseMimeType` + `responseSchema` | 자유 텍스트 파싱보다 안정적. 스키마 위반은 실패 처리 |
| **temperature** | `0.0` | 판정 작업 — 같은 입력이면 같은 답이 캐시와도 맞는다 |
| **회로 차단기** | 연속 3회 실패 → **5분 중단** | 키 오타·할당량 소진 상태에서 배치가 곡마다 8초씩 까먹는 걸 막는다 |
| **즉시 차단** | 429 · 403 · 401 · 400 | 재시도해도 같은 결과 → 바로 회로를 연다 |
| **일일 상한** | `AI_DAILY_CAP` 기본 1000 | 무료 티어 보호 |
| **결과 캐시** | SHA-256(작업명 + **프롬프트 버전** + 입력), TTL 90일 | 프롬프트를 고치면 버전을 올려 옛 답을 자동 무효화 |
| **곡당 검증 예산** | 2회 | 사다리 단마다 검증하면 곡당 5회가 쌓여 화면이 수십 초 멈춘다 |
| **API 키 전달** | `x-goog-api-key` **헤더** | 쿼리스트링에 넣으면 프록시·서버 로그에 그대로 남는다 |

**왜 Gemini flash-lite 인가**: A·B 는 곡당 1회이고 결과를 DB 에 캐시하므로 총 호출량이 작다.
무료 티어로 충분하고, **서버의 CPU 를 전혀 쓰지 않는다** — 저사양 기기에서 돌리는 서버라 이게 컸다.
로컬 3B 양자화 모델도 재봤지만 **곡당 수십 초라 배치가 성립하지 않았다.**

## 6. API

| 메서드 | 경로 | 하는 일 |
|---|---|---|
| `GET` | `/api/lyrics/{vid}` | 가사 조회 — 없으면 사다리를 돌려 찾아온다 |
| `POST` | `/api/lyrics/{vid}/layers?force=` | 일본어 가사에 발음·번역 붙이기 (도구 C) |
| `GET` | `/api/admin/ai` | **에이전트 상태** — 모델 · 오늘 호출수 · 상한 · 회로 상태 |
| `POST` | `/api/admin/ai/cache/purge?all=` | AI 결과 캐시 비우기 |

## 7. 설정

AI 기능은 **전부 선택**이다. 키를 넣지 않으면 조용히 꺼지고 규칙 기반 경로만 돈다.

```bash
GOOGLE_AI_API_KEY=          # 비우면 AI 기능 전체 꺼짐 (서비스는 정상 동작)
AI_MODEL=gemini-3.5-flash-lite
AI_DAILY_CAP=1000           # 하루 호출 상한
AI_TITLE_ENABLED=true       # 도구 A
AI_VERIFY_ENABLED=true      # 도구 B
AI_LYRICS_ENABLED=true      # 도구 C
NAMU_LAYERS_ENABLED=true    # 도구 C 의 1순위(사람이 쓴 발음·번역) 소스
```

전체 항목은 [`.env.example`](.env.example) 참고. 키 발급은 <https://aistudio.google.com/apikey>.

> 🔒 **`.env` 는 절대 커밋하지 않는다.** 이 저장소에는 `.env.example`(placeholder 만) 이 들어 있다.

## 9. 기술 스택
